Fixed: when provider discovery finishes while the session model picker is open, the picker now rebuilds in place and stays on the user's tab. The regression test fails on the base and passes after the fix. Clippy is clean for `codex-tui`.

**Cause:** when discovery finished, `provider_manager_statuses_resolved` updated the cached availability policy but never touched the picker already on screen, so a restored OpenAI stayed missing until the picker was reopened.

## Changes
- **`codex-rs/tui/src/chatwidget/model_popups.rs`**
  - Split the picker's row-building into a new `all_models_popup_params(...)` function. Opening the picker behaves as before, including the "No additional models are available right now." message.
  - Only the session picker gets an ID (`"session-model-picker"`), so the spawn-agent and codex-pane pickers are not refreshed.
  - New `refresh_open_session_model_picker()` does nothing unless the session picker is the top view. It rebuilds the rows from the current catalog, using the same filter as `/model`, and keeps the user's tab if that tab still exists.
  - Because it only acts on the top view, it never reopens a dismissed picker and never replaces a reasoning dialog stacked above it. It also doesn't rebuild the picker underneath that dialog, because doing so would lose the setting that closes the picker after the dialog is accepted.
- **`codex-rs/tui/src/app/provider_management_status.rs`**: calls the refresh right after `update_provider_statuses` when discovery finishes.
- **`codex-rs/tui/src/app/tests/provider_picker_refresh.rs`**: two new tests. Both save synthetic Z.AI and DeepSeek keys in File credential mode, then open `/providers` and dismiss it.
  - `late_provider_recovery_refreshes_open_model_picker_and_keeps_tab` (the regression test): opens the picker and moves to the DeepSeek tab. After OpenAI is restored and the late result arrives, it checks that OpenAI appears, DeepSeek is still the selected tab, and `/providers` didn't reopen. It includes a snapshot.
  - `late_provider_recovery_leaves_dismissed_picker_and_reasoning_dialog` (guard test): checks that a late result doesn't reopen a dismissed picker or change an open reasoning dialog. It also passes on the base, as expected for a guard.
- **New snapshot:** `codex-rs/tui/src/app/tests/snapshots/codex_tui__app__tests__provider_picker_refresh__open_model_picker_after_openai_recovery.snap`, showing the tabs as `OpenAI  Z.AI  [DeepSeek]`.
- **Release note:** `qa/release/unreleased/notes/2102-open-model-picker-provider-recovery.md`. `release_notes.py check` reports "65 release-note fragment(s) OK".
