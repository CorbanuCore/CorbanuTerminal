### F6 (case A01: checkout /Volumes/CorbanuDrive/Corbanu/.codex-work/bench-astra-20261114/wt/a01, diff 2cfd034860f792d0c3605b40437a3e21e29b361e..HEAD)

Medium: `chroot` is found only as the plain command or directly after `eval`. Trivial rewordings still hide its command.
- Where: `codex-rs/core/src/security/tainted_action.rs:2571-2577` and `:2606-2607`, together with `indirect.rs:807`.
- What's wrong: chroots are looked for in only two places: in `programs(words)` (`from` 0) and right after `eval` (`operands = eval index + 1`). The classifier already handles other ways a line can carry a command. `carried_command` (around line 2775) handles `eval --`, `eval eval`, `trap`, `coproc` and `repeat`. `after_modifiers` handles zsh's `noglob`, `nocorrect` and `-`. The new chroot code checks neither.
- Example: in `eval -- chroot / ./x`, `programs(["--","chroot",...])` returns `--` as the command. `chroot_commands` and `chroot_runs_unjudged` therefore never see the chroot. So these lines likely stay quiet, just as `chroot / ./x` was quiet before this change, while their plain forms now ask:
  - `eval -- chroot / ./x`
  - `eval eval chroot / ./x`
  - `noglob chroot / ./x` (zsh)
  - `trap 'chroot / ./x' EXIT`
  - `coproc chroot / ./x`
  - `eval -- chroot /tmp/r ls`, which also skips the new "another root" prompt
- Fix: run `chroot_commands` and `chroot_runs_unjudged` from the start of each carried span and from the start after the zsh modifiers, not only from `eval index + 1`. This means computing `carried_command` and `after_modifiers` before the chroot block. Add these spellings to `issue1808_chroot_judges_its_command`.
