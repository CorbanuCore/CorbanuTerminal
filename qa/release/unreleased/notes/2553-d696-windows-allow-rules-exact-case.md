## Security

On Windows, `allow` command rules (including remembered "always allow" rules) now approve only the program name exactly as the rule spells it, as on macOS and Linux (D696, #2553). Before, Windows read a command's program by its lower-cased name without `.exe`, `.cmd`, `.bat` or `.com`, so an `allow` rule for `rm` or `git push` also approved `RM x`, `GIT.EXE push` or `C:\Program Files\Git\cmd\git.exe push`. Those now ask first. A path whose file name is spelled as in the rule (`C:\tools\git push` for `git`) is still allowed, and so is a path listed by `host_executable` exactly as listed, drive letter case included; to approve `git.exe` by path without a prompt, list that path with `host_executable(name="git", ...)`. `forbidden` and `prompt` rules still match every Windows spelling. Existing rules files load unchanged, including their `match` and `not_match` examples; only which commands `allow` rules approve without asking has narrowed.
