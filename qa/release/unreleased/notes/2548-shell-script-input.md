## Security

Command rules now read shell scripts default-deny. `eval` with known words and a literal here-document or here-string given to a shell are read as scripts, including behind launchers, reserved prefixes (`time`, `!`, `coproc`) and function bodies, so a forbidden command inside is refused. Wherever a script holds a shape the reader does not fully understand, it asks for approval whenever a prompt or forbidden rule exists: a shell reading a pipe or file, `source`/`.`, `eval` of unknown words, `trap`, `alias`, arithmetic (`$((…))`, `[[ $x -gt 1 ]]`), array subscripts, backquotes, `set -x` and variables such as `BASH_ENV` or `PS4`. Such scripts never offer an "always allow" amendment. In a POSIX shell script, PowerShell given words known only at run time now asks too (#2548, #2585, D553).
