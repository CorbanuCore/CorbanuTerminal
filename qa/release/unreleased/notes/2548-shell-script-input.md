## Security

Command rules now read shell scripts fail-closed. A script is read precisely only if it uses a minimal set of shell syntax every shell reads the same way (plain words and quotes, `&&`, `||`, `;`, `|`, `$?`-style status values and one simple redirection per command); within it, `eval`, a shell given its own here-document or here-string, reserved prefixes (`time`, `!`, `coproc`) and function bodies are read too, so a forbidden command inside is refused. Any other script (variables, command substitution, here-documents, tests in brackets, `case`, arithmetic, backquotes and so on) asks for approval whenever a prompt or forbidden rule exists; with none, nothing changes. Builtins that run code (`source`, `trap`, `alias`, `let` and the like, also through wrapper programs such as `/usr/bin/jobs`), a shell reading a pipe or file, and ksh-family `-c` scripts also ask. **Under Aggressive with approvals off (headless), shell scripts that use variables, command substitution or other non-trivial syntax are now refused: 25.8% of a 5,000-script corpus of real agent commands (3.4% before).** In a POSIX shell script, PowerShell given words known only at run time now asks too (#2548, #2585, D553).
