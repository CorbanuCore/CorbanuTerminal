## Security

Command rules now read shell scripts fail-closed. A script is read precisely only if it uses a set of shell syntax every shell reads the same way: plain words and quotes, `&&`, `||`, `;`, `|`, `$?`-style status values, one simple redirection per command, variables as arguments (`$x`, `${x:-default}`, `${x#pattern}`), arithmetic on numbers, command substitution (`$(…)` and backquotes) whose commands are read the same way, and one-line `[ … ]` and `[[ … ]]` tests. Within it, `eval`, a shell given its own here-document or here-string, reserved prefixes (`time`, `!`, `coproc`) and function bodies are read too, so a forbidden command inside is refused. Any other script (a variable or substitution naming the command, arithmetic on variables, here-documents, `case`, subshells, several redirections on one command and so on) asks for approval whenever a prompt or forbidden rule exists; with none, nothing changes. Builtins that run code (`source`, `trap`, `alias`, `let` and the like, also through wrapper programs such as `/usr/bin/jobs`), a shell reading a pipe or file, and ksh-family `-c` scripts also ask. **Under Aggressive with approvals off (headless), shell scripts that use other syntax are now refused: 13.1% of a 5,000-script corpus of real agent commands (3.4% before).** In a POSIX shell script, PowerShell given words known only at run time now asks too (#2548, #2585, D553, D713).
