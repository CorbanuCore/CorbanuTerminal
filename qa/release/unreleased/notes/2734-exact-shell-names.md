## Security

Command rules read a shell's script only when the shell is named exactly (`bash`, `/bin/zsh`, `sh`, `pwsh.exe`, `C:\…\powershell.exe`, or the shell's name with `.exe`), or spelled in a way the platform itself runs as that shell (`PWSH.EXE`, `pwsh.exe.` on Windows). A name that only looks like a shell through another extension (`pwsh.evil.exe`, `pwsh.bat`, `bash.sh`, `bash.foo.exe`, or the NTFS stream `bash.exe:x.exe`) runs another file, possibly one the agent wrote: its `-Command`/`-c` script is no longer read as that file's commands, a remembered approval for the script no longer covers it, and it asks wherever a prompt or forbidden rule exists, without offering an always-allow rule (#2734). On Windows, under a prompt or forbidden rule, a PowerShell script is now also read only in part, so it asks, when it is passed with `-EncodedCommand` (which runs without the launcher's module hardening), when the command's environment has no `PATH`, when an allowlisted cmdlet after the first command of a pipeline has an excluded parameter that can take pipeline input (such as `-ComputerName` or `-Credential`), or when it names a drive letter that is not a local disk (a mapped network drive, or one not present yet) (#2756).
