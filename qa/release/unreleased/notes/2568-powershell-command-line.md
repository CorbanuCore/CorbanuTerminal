## Security

On Windows, command rules read a PowerShell command line the way PowerShell does (#2568, D553). PowerShell runs every argument after `-Command` as one script, so `powershell.exe -Command "git status" "; git push"` runs `git push`; rules used to see only `git status`, and now see both. `-EncodedCommand` scripts are decoded and read, and abbreviated parameters (`-c`, `-nop`, `-ec`, `/Command`, `--command`) are read as PowerShell reads them. A command line rules cannot read that way (an unknown parameter such as `-NoExit`, a script from stdin, `-CommandWithArgs` with arguments, a positional script) now asks for approval whenever a prompt or forbidden rule could match it, as an unread script already did; `-File` scripts are checked as their file and arguments and ask the same way. With no prompt or forbidden rule, nothing changes. The commands treated as safe to run without asking read the same script, so `powershell.exe Get-Content "x; Remove-Item y"` is no longer treated as a read-only command. The PowerShell that reads scripts is no longer taken from the current folder under another spelling (letter case, 8.3 short name, junction), or from a `%SystemRoot%`/`%ProgramFiles%` that is a network or device path.
