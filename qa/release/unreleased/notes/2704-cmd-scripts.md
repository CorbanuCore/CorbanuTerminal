## Security

Commands run through cmd.exe (`cmd /c …`, `cmd /k …`, `cmd.exe /d /c …`, or cmd.exe reading its input) now ask for approval whenever a prompt or forbidden command rule exists, also inside PowerShell scripts, because rules cannot read the script cmd.exe runs: previously `cmd /c "git push"` ran unasked under a rule forbidding `git push`. The same applies when a program that may be a batch file is given an argument with a character cmd.exe reads as more than text (`& | < > ^ % ! " ( )` or a line break), since cmd.exe re-reads a batch file's arguments: a program named `.cmd` or `.bat`, and on Windows a path not named `.exe` or `.com` (`.\build`) or a name found on `PATH` as a batch file (`pnpm` found as `pnpm.cmd`). With approvals off (including Aggressive with approvals set to never) these commands are refused, and the prompt never offers an always-allow rule (#2704, D553).
