## Windows sandbox

- In the Windows sandbox, a program given with separate arguments after `cmd.exe /C` is now refused instead of run when it would parse those arguments as a command line again and an argument contains a character cmd acts on (`" % ! ^ & | < > ( )` or a line break): a nested `cmd`/`cmd.exe` (any case or path), the `start`, `if` and `for` builtins (which run a command taken from their arguments), or a name cmd finds through PATHEXT as a batch file (for example `npm` for `npm.cmd` in the working directory or on `PATH`, or a drive-relative name such as `C:npm`). Previously such an argument (for example `a&b` passed to `cmd /c cmd /c x`) could run text after it as a separate command. A program merely in a folder named `cmd` (such as Git's `Git\cmd\git.exe`) is not affected. The same programs with plain arguments, and a single command line after `/C`, run as before (#2718).
