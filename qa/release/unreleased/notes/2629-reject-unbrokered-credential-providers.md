## Security

- A configured network proxy credential provider that names an environment variable Corbanu's credential engine does not broker is now refused when the config loads, with an error naming the provider and the variables. Before, it loaded and its values were silently withheld from every command (D612, #2629). Corbanu brokers only its built-in credential variables: `GH_TOKEN`, `GITHUB_TOKEN`, `GH_ENTERPRISE_TOKEN`, `GITHUB_ENTERPRISE_TOKEN` and `OPENAI_API_KEY` (names compare case-insensitively on Windows).
  - **Configs that now fail to load:** a `[features.network_proxy.credentials.<name>]` table, in `config.toml` or in a profile config file selected with `--profile`, whose `env` lists any other variable, when `features.credential_masking` is on, or when the `network_proxy` feature is on and the permission profile allows network access. Project configs already ignore this table. This applies even when `network_proxy.credential_broker = false` leaves the table unused, and to managed or cloud config layers, where it stops the config from loading for every user. If the starting permission profile has no network access, the error appears when switching to one that has.
  - **Fix:** remove that provider or those variables. To keep a variable away from commands, add it to `shell_environment_policy.exclude`.
  - Providers that list only built-in variables load as before. The built-in engine masks those variables, or withholds one it cannot mask (for example `GH_ENTERPRISE_TOKEN` without `GH_HOST`). The run-time withholding stays as a second guard.
  - No default or shipped config or profile names such a provider; the tests that did were updated.
