## Security

On Windows, a PowerShell script is now read as its commands only when every command is a native program or a cmdlet on an allowlist of cmdlets that run nothing but their own arguments (file and text queries, object shaping, output, and file writes), used without the parameters that set variables, prompt or run code, and writing only inside the session's writable roots (the workspace under full access), never a file Windows runs from a folder (`.cmd`, `.exe`, `.dll`, …) and never into or above a PowerShell module, profile or `PATH` folder; every program it runs must be a program on the command's `PATH`, and the shell must run with `-NoProfile` or have no profile script. Any other command (another cmdlet or function, a module's command not yet loaded, a script file, `Start-Process`, `ForEach-Object` member calls, `Expand-Archive`, writes to `env:`, the registry or links) makes the script ask whenever a prompt or forbidden command rule exists, as other unread scripts do, and it is refused with approvals off (including Aggressive with approvals set to never). Commands rules can see in it are still refused. Aliases and built-in names come from fixed tables for Windows PowerShell 5.1 and PowerShell 7, and the trusted parser now starts with module autoloading off and loads only PowerShell's own system modules. On a corpus of 2,492 agent PowerShell scripts with one unrelated forbidden rule (what every Aggressive session has), the share that asks rises from 66.3% to 71.4% on Windows PowerShell 5.1 and 71.3% on PowerShell 7.7 (cmd.exe scripts asking under #2704 account for 66.3% to 69.1%); asking for every script would be 100% (#2661, D729).
