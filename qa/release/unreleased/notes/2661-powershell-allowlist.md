## Security

On Windows executors, a PowerShell script is now read as its commands only when every command is either a native program found on the command's `PATH` or a cmdlet on an allowlist of cmdlets that run nothing but their own arguments and write no file (file and text queries, object shaping, output, local process, service and job queries), used without the parameters that set variables, prompt, reach another computer or ask for credentials, with no network or provider-qualified path (`\\host\share`, `FileSystem::…`), in a shell started with `-NoProfile` or with no profile script. Any other command (another cmdlet or function, a module's command or alias, a script file, `Start-Process`, `ForEach-Object`, and every cmdlet that writes, copies, moves, renames, removes or downloads files, including `Invoke-WebRequest` and `Invoke-RestMethod`, and WMI/CIM queries, `Test-Connection` and `Stop-Process`) makes the script ask whenever a prompt or forbidden command rule exists, as other unread scripts do, and it is refused with approvals off (including Aggressive with approvals set to never). Commands rules can see in it are still refused. In this reading, a name the agent's shell defines before its script runs is not taken for a program, even when a program of that name is on `PATH`, since PowerShell runs its own command instead: the commands, aliases and functions of the system modules Corbanu's PowerShell launcher imports (#2710, D731), such as `rcim`, `gin`, `Compress-Archive` or `Invoke-Expression`, and those PowerShell itself defines; unless allowlisted, such a name makes the script ask. This stricter reading applies only where a prompt or forbidden command rule exists: without one, scripts are read as before (D733). Corbanu reads these scripts without starting PowerShell, also for a Windows executor on another host: the allowlist, aliases, built-in names and cmdlet parameters come from fixed tables of Windows PowerShell 5.1 and PowerShell 7.7, and for a remote Windows executor no program or module command can be looked up and a profile may exist, so a script that runs one, or a shell started without `-NoProfile`, asks under these rules (#2661, D729). A network path built while the script runs is not detected; reading it runs no program.
