## Security

On Windows, a PowerShell script is now read as its commands only when every command is either a native program found on the command's `PATH` or a cmdlet on an allowlist of cmdlets that run nothing but their own arguments and write no file (file and text queries, object shaping, output, local process, service and job queries), used without the parameters that set variables, prompt or run code with switches given no value and with no network or provider-qualified path (`\\host\share`, `FileSystem::…`), in a shell started with `-NoProfile` or with no profile script. Any other command (another cmdlet or function, a module's command or alias not yet loaded, a script file, `Start-Process`, `ForEach-Object` member calls, and every cmdlet that writes, copies, moves, renames, removes or downloads files, including `Invoke-WebRequest` and `Invoke-RestMethod`, and WMI/CIM queries, `Test-Connection` and `Stop-Process`) makes the script ask whenever a prompt or forbidden command rule exists, as other unread scripts do, and it is refused with approvals off (including Aggressive with approvals set to never). Commands rules can see in it are still refused. Aliases and built-in names come from fixed tables for Windows PowerShell 5.1 and PowerShell 7, and the trusted parser now starts with module autoloading off and loads only PowerShell's own system modules. On a corpus of 2,492 agent PowerShell scripts with one unrelated forbidden rule (what every Aggressive session has), the share that asks rises from 66.3% to 72.2% on Windows PowerShell 5.1 and PowerShell 7.7 (cmd.exe scripts asking under #2704 account for 66.3% to 69.1%; for the 951 commands of real Windows agent sessions, 49.3% to 58.1%); asking for every script would be 100% (#2661, D729). A network path built while the script runs is not detected; reading it runs no program.
