## Security

On Windows, agent PowerShell commands now start with module autoloading off and load the system modules PowerShell's own commands come from (Management, Utility, Security, Archive, CIM) from PowerShell's install folder, so a module written into a user module folder can no longer replace a cmdlet an agent's script calls (#2661, D729, D731). Commands from other modules (for example `Get-ScheduledTask`, `Get-NetTCPConnection`, `Get-LocalUser`) now need an explicit `Import-Module`, which asks for approval under strict command rules; this affected 1.7% of 951 PowerShell commands from real agent sessions on Windows (3.3% of a wider corpus of 2,492 agent PowerShell scripts), on Windows PowerShell 5.1 and PowerShell 7.7 alike.
