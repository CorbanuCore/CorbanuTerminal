## Security

On macOS and Linux, a PowerShell command line (`pwsh -Command …`) now asks for approval whenever a prompt or forbidden command rule exists, because PowerShell scripts are read only on Windows; with no such rule it still runs unasked but no longer offers an always-allow rule for the whole command line. On Windows, PowerShell commands that rebind a command name through a literal argument (`Set-Alias`, `New-Alias`, `Import-Alias`, paths on the `alias:` or `function:` drive, `New-PSDrive`) or run code given as text, a module or a file (`Invoke-Expression`, `Import-Module`, `Add-Type`, `Invoke-Command`, `Start-Job`) ask the same way, as bash's `alias`, `hash -p` and `trap` already do. This narrows, but does not close, the ways a readable PowerShell script can hide a command from rules on Windows (#2601, #2661, D553).
