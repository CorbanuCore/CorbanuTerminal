Opus 5.5 High vs Astra High on our own work (2026-11-14)

Version 1 (progress): Track A (review benchmark) is scored. Track B (paired implementation and blind grading) is still running; its sections fill in when it finishes. Prepared by bench-1114.

In short

Question. Can Astra High (gpt-6-astra, reasoning high) take some of the work Opus 5.5 High does now, so we get more done? We tested both models on our real work: reviews of past pull requests where we already know the bug (Track A), and the same implementation tasks given to both (Track B).

Track A result. Astra High found more of the known bugs: 6 of 8 fully, against Opus's 3 fully and 2 partly. On the three security-classifier changes, Astra found the known bug all 3 times; Opus found none fully and one partly. Opus did better on reading user-interface and agent-control code, where it found more of each bug's related parts. Both missed the dependency-upgrade bug (#1962). Each model gave one wrong verdict on top of that: Opus approved a change with a real bug (#1055), and Astra blocked a clean change (#1944) over a point that is technically right but low-impact.

Careful: 8 bugs and 2 clean controls, one run per model, is a small sample. Three of the eight bugs were first found by Astra during the November 11 reviews, so this set may favour Astra. Read the result as "Astra is a credible first reviewer", not "Astra is better than Opus".

Track A — review benchmark (known defects)

We took 8 past pull requests where an independent review found a real bug that was then confirmed and fixed, plus 2 merged pull requests where nothing was ever found (controls). We put each one back at the exact version that had the bug. Each model got the same neutral brief ("find defects, give severity and file:line, end with a verdict"), with no hint of the bug, in a copy of the repository that contained no later history. We wrote the answer key and froze it (sha256 recorded) before any model ran.

Scoring: "found" means the review named the bug's mechanism and place. "Partly" means the right area or one of two main bugs. Extra findings were checked against the code. When we could not settle one by reading, it was marked uncertain and sent to blinded grading.

Where each model was stronger. Astra found three security-classifier bugs that Opus missed or only partly found (#1837, #1055, #2133), including the exact line in #2133. Opus covered more related parts in the agent-control bug (#1175: it also found the kill-switch re-check) and partly found the #1171 bug that Astra missed. Both found the dropped network settings in the sync resolution (#2043) and the Windows test bug (#1889).

Both missed #1962, a lock-file-only upgrade of assert_cmd. In the new version, an unchanged helper's call panics where it used to return an error. The new version's source was not on disk and the network was off, so this tests prior knowledge more than review skill.

Wrong verdicts: Opus approved #1055, which has a real defect. Astra blocked the clean control #1944, saying GIT_ALLOW_PROTOCOL=file re-allows local-file submodule clones that git blocks by default. Git's documentation supports that, but the sandboxed command could read those files directly anyway, so a blocking verdict is too strong. Astra was more willing to block; Opus was more willing to approve.

Track B — paired implementation

Four tasks, each done once by each model, in separate copies of the repository from the same starting commit. B1 and B2 re-implement fixes we merged recently (#2046 guardian stop gap, #2102 provider picker refresh), starting from the issue text alone. B3 resolves a real upstream-sync conflict (codex-agent-roles, as in #2059). B4 is a fresh open issue (#2018, classifier brace groups). Hidden check: the merged fix's own tests (or compile and clippy for B3), run on each solution afterwards. Rubric: two blinded graders (one Opus, one Astra) scored each pair of solutions labelled only X and Y.

Caveats

  • Small sample: 8 known bugs and 2 controls, one run per model per case. One different answer moves a total by 12 percentage points.
  • Selection bias: the bugs in #1837, #1055 and #2133 were first found by Astra High reviews on November 11; the bugs in #2043, #1171, #1175 and #1889 were first found by Opus. Per-case results are shown so readers can see this.
  • Reviews were read-only, with no builds or tests. Both models could read the repository and the local cargo registry, but not the network.
  • The Opus log header does not print the reasoning effort for the claude-plan provider. The same model_reasoning_effort="high" flag that our standing reviewers use was passed to both models.
  • Scoring of extra findings is our judgement against the code; uncertain ones go to blinded graders.
