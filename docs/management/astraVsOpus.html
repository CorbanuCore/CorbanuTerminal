Opus 5.5 High vs Astra High on our own work (2026-11-14)

Final version, 2026-11-14 (prepared by bench-1114). Track A (review benchmark) and Track B (paired implementation, hidden checks, blinded two-grader rubric) are complete. A small variance rerun of B1 is reported separately.

In short

Question. Can Astra High (gpt-6-astra, reasoning high) take some of the work Opus 5.5 High does now, so we get more done? We tested both models on our own work. Track A: reviews of 10 past pull requests where we already know the answer. Track B: 4 identical implementation tasks, checked with hidden tests and graded blind by one Opus grader and one Astra grader.

Short answer: yes, for most everyday work, with Opus still doing the final review. Astra was at least as good as Opus on almost everything we measured. Neither model was reliable enough to work without a second reviewer.

Reviews (Track A). Astra found more of the known bugs: 6 of 8 fully, against Opus's 3 fully and 2 partly. It was strongest on security-classifier code (3 of 3; Opus 0 fully, 1 partly). Opus raised more additional real issues (23 against 14) and was stronger on agent-control/TUI code. Both missed one dependency-upgrade bug. Opus wrongly approved one buggy change. Astra blocked one 'clean' control, and two graders later judged its reason a real, previously unnoticed issue (#1944, see Decisions).

Implementation (Track B). Both models passed the hidden checks on 3 of 4 tasks, and both missed the same detail on the fourth (B2: the open model picker should keep the tab the person was on). On the blind rubric, both graders preferred Astra's work on B1 and B4 and Opus's on B3, and split on B2. On the security-classifier task (B4), Opus's change made 4 shell lines quieter than before, against the task's explicit rule; Astra kept the old verdict as a floor. Opus's sync resolution (B3) and its tests were better. A second run of B1 gave the same outcome for both models. Wall time was similar, and Astra used about 40–75% more tokens per task.

Careful: this is a small sample: 8 known bugs, 2 controls and 4 tasks, mostly one run each. Three of the known bugs were first found by Astra, and four by Opus. The graders showed a mild lean towards their own model's work. Treat the differences as tendencies, not rankings.

Track A — review benchmark (known defects)

We took 8 past pull requests where an independent review found a real bug that was then confirmed and fixed, plus 2 merged pull requests where nothing was ever found (controls). We put each one back at the exact version that had the bug. Each model got the same neutral brief ("find defects, give severity and file:line, end with a verdict"), with no hint of the bug, in a copy of the repository that contained no later history. We wrote the answer key and froze it (sha256 recorded) before any model ran.

Scoring: "found" means the review named the bug's mechanism and place; "partly" means the right area or one of two main bugs. Extra findings were checked against the code. The 13 we could not settle ourselves went, unattributed, to both graders, who rated all 13 real.

Where each model was stronger. Astra found three security-classifier bugs that Opus missed or only partly found (#1837, #1055, #2133), including the exact line in #2133. Opus covered more related parts in the agent-control bug (#1175: it also found the kill-switch re-check) and partly found the #1171 bug that Astra missed. Both found the dropped network settings in the sync resolution (#2043) and the Windows test bug (#1889).

Both missed #1962, a lock-file-only upgrade of assert_cmd. In the new version, an unchanged helper's call panics where it used to return an error. The new version's source was not on disk and the network was off, so this tests prior knowledge more than review skill.

Verdicts. Opus approved two changes that had real bugs (#1962, #1055); Astra approved one (#1962). On the control #1944, Astra requested changes. Its reason was that GIT_ALLOW_PROTOCOL=file re-allows local-file submodule clones that git blocks by default. Both blinded graders later judged this real (medium by the Opus grader, high by the Astra grader). So it is not a false alarm, and #1944 was probably not as clean as we thought. We show its verdict as debatable rather than wrong.

Extra findings. Beyond the known bugs, Opus raised 23 real issues and Astra 14, with no false ones (after grading). Opus tends to list more related problems; Astra tends to focus on the main defect. Using both as reviewers would combine the two.

Track B — paired implementation

Four tasks, each done once by each model, in separate copies of the repository from the same starting commit. B1 and B2 re-implement fixes we merged recently (#2046 guardian stop gap, #2102 provider picker refresh), starting from the issue text alone. B3 resolves a real upstream-sync conflict (codex-agent-roles, as in #2059). B4 is a fresh open issue (#2018, classifier brace groups). Hidden check: the merged fix's own tests (or compile and clippy for B3), run on each solution afterwards. Rubric: two blinded graders (one Opus, one Astra) scored each pair of solutions labelled only X and Y.

B1 (#2046, core concurrency). Both solutions pass the merged fix's hidden tests (2/2), and each one's own test fails before and passes after. Both graders preferred Astra's: it holds the turn lock for the whole ownership check, with fuller assertions. Opus's report wrongly said strict clippy fails with the pinned toolchain; our rerun with 1.99.1 passes for both. The 1.95.0 default on the worker machines does fail, on 10 errors in files neither solution touched (see Decisions).

B2 (#2102, TUI). Both solutions fail the same hidden snapshot test. When OpenAI comes back while the model picker is open on the Claude Plan tab, both pickers jump to the OpenAI tab; the merged fix keeps the person's tab, which the issue asks for. Each solution's own "keeps tab" test covered a different case. The graders split, each preferring its own model's work. Astra also added a QA reliability note, and Opus left a tidier diff.

B3 (sync conflict, codex-agent-roles). Both resolutions are byte-identical to the maintainers' merged resolution in agent-roles/src. Both compile, pass clippy and pass the hidden behaviour test (3/3). Opus also added 97 lines of tests; Astra added none. Both graders preferred Opus's.

B4 (#2018, security classifier, fresh issue). Both pass the full classifier suite (905 and 907 tests) and clippy, and both have new tests that fail before and pass after. Both graders preferred Astra's. Opus's simpler fix makes ! { echo ok; } | bash and time { echo ok; } | bash quieter than before (UnseenCode → nothing). We confirmed this with a probe after grading; it breaks the task's "never quieter" rule. Astra kept the old verdict as a floor, which gives up part of the issue's precision goal but stays safe.

Graders. They agreed on 3 of 4 preferences, gave exactly the same score on 32 of 48 paired dimension scores, and differed by 0.40 points on average. Each gave its own model's work a higher total, by 2 to 7 points out of 30 per task, so blind grading by a single model would slightly favour that model. Using both graders evens this out.

Variance (B1 run twice). We ran B1 a second time for each model, from fresh clones. Both again passed the hidden tests, with own tests failing before and passing after. Both graders again preferred Astra's on correctness, although both gave Opus's work a slightly higher total (27 against 25 and 26). Run times swapped between the runs (Opus 28 then 38 minutes; Astra 31 then 27). Astra again used more tokens (292k and 205k, against Opus's 124k and 116k). In its second run, Opus correctly spotted the toolchain mismatch that had misled it in the first.

Cost

Totals: Track A, Opus 27 min and 969k tokens, Astra 29 min and 877k tokens (10 reviews each). Track B, Opus 88 min and 533k tokens, Astra 91 min and 756k tokens (4 tasks each). Opus runs on the Claude plan (limited capacity, with a multi-day cooldown this week); Astra runs on the OpenAI provider. The token counts are each harness's own report, and the two providers count differently.

Caveats

  • Small samples: 8 known bugs and 2 controls in Track A, and 4 tasks in Track B, mostly one run per model. One different outcome moves a Track A total by 12 percentage points.
  • Selection: three of the known bugs (A01, A03, A05) were first found by Astra High on November 11, and four (A04, A06, A07, A08) by Opus. Results are shown per case so this is visible.
  • Track A reviews were static (no builds) and offline. A02 depended on knowing about the assert_cmd 2.2 change, which could not be looked up.
  • Hidden checks: for B1 and B2, the merged fix's tests were added unchanged as an extra module, so they ran next to each solution's own tests. B4 has no reference fix. Integration-test suites (--test all) were not run, only the lib suites, to save time.
  • Blinding: graders saw X and Y with model names, token counts and arm paths removed. Writing style may still hint at the model. The experiment folder name contains 'astra' for both sides. For B2 the task itself is about model names, so we removed paths only.
  • The Opus log header does not print reasoning effort for the claude-plan provider. Both arms got the same model_reasoning_effort="high" flag.
  • Astra's implementation logs each list exactly 78 commands, so its exec log may be capped. GitHub compliance therefore also relies on the clones having no remote and on our GitHub activity check, which found no writes by any arm.
  • Track A extra findings: 13 we could not settle ourselves went to both graders, unattributed. Both graders rated all 13 real.

Decisions for Travis

  1. Allow Astra High as the implementer and first-pass reviewer for ordinary bug fixes, CI/flake work, docs, triage and sync conflicts, keeping today's independent Opus 5.5 High review before every merge. Options: (a) yes, as recommended; (b) only first-pass review, not implementation; (c) not yet, more data first. Recommendation: (a). This raises throughput where Opus capacity is the limit, and the safety net stays the same.
  2. Security work: keep Opus as the only security sign-off (D318), but add Astra as a required second reviewer on security-classifier PRs. Options: (a) add Astra as a second lens, as recommended; (b) leave as is. Recommendation: (a). Astra found 3 of 3 classifier bugs in Track A, and Opus 0 fully.
  3. New finding to triage (the experiment could not file issues): #1944 sets GIT_ALLOW_PROTOCOL=file in the Windows no-network sandbox. That makes git treat the file transport as always allowed, which lifts git's default protocol.file.allow=user guard for submodules, so a hostile .gitmodules can clone a local repository. Both graders judged it real (medium / high). Impact is limited, because the sandboxed command could read those files directly. Recommendation: file an issue; a fix could keep file but restrict it for submodules, e.g. by setting GIT_PROTOCOL_FROM_USER=0.
  4. Toolchain on worker machines: the default rustc on PATH is 1.95.0, while codex-rs/rust-toolchain.toml pins 1.99.1. Under 1.95.0, strict clippy reports 10 errors in untouched code, and Opus reported that as a gate failure twice in this experiment. Recommendation: put the pinned toolchain first in the worker PATH (decision-free; a coordinator change).
  5. #2018 is still open. Both experimental fixes exist only locally, in .codex-work/bench-astra-20261114/wt/b4-*. Astra's kept the never-quieter rule. The issue was offered to contributor @ryssroad, so check with them before a maintainer picks it up.
